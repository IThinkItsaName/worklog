# 约定（Conventions）

> 这些是硬约定。`journal.py check` 按本文件实现校验；偏离前先想清楚代价，偏离后要在记录里写明。

## 目录布局

```
<项目根>/
├── journal/
│   ├── README.md             ← 唯一台账：索引表 + 同主题簇 + 滚动待办 + 当前状态
│   ├── 0001-<slug>.md        ← 过程记录，一篇 = 一个变更集
│   ├── 0002-<slug>.md
│   └── archive/
│       ├── README.md         ← 归档索引 + 编号换算（归档不改号）
│       ├── STATUS-HISTORY.md ← 被替换下来的旧「当前状态」块
│       └── <stage>/NNNN-*.md
└── lessons/
    ├── README.md             ← 分册索引 + 使用方式
    ├── 01-<topic>.md
    ├── ...
    └── 99-retrospectives.md  ← 阶段复盘（承接 SUMMARY 的职责）
```

- 目录名可用 `journal/`，也允许沿用既有名字（如 `work-log/`）。**只看行为，不强制改名。**
- 记录文件名：`NNNN-kebab-or-中文扼要.md`，编号 4 位（历史文件早已是 1–3 位则不要重命名）。
- 编号**单调递增、永不复用**，归档不改号。

## 两个计数器（不要混）

| 名字 | 含义 | 在哪 | 规则 |
|---|---|---|---|
| **篇号** | 记录文件编号，索引与回指的地址 | 文件名 + 标题 `# 0007 · ...` | 每写一篇 +1；永不复用；跨归档不变 |
| **变更集号** | 产品/仓库层面的迭代号（一个可交付改动） | 记录入口的 `变更集: N` 字段 | 一个变更集可以对应多篇（如"实施 + 验收修复"）；一次性调研记 `变更集: -` |

回指统一写 `wl/NNNN`（篇号），不要写"变更集 N"，否则两者会混淆。

## 记录生命周期

```
草稿（进行中）  →  收口（closed）  →  （可选）归档
```

- **草稿**：标题下方元数据可边做边补；允许写"未验证/待确认"。
- **收口**：收尾清单（见 SKILL.md）全部完成后才算 closed。收口后**不改写已发生的结论**。
- **更正**：新证据推翻旧结论时，**追加** `## 更正` 段（日期 / 原结论 / 新证据 / 现结论），并同步台账与 lessons；
  绝不允许把旧文字直接抹掉。
- **归档**：阶段收口、索引表停止增长时，把整阶段的记录 move 到 `journal/archive/<stage>/`；
  同步改索引链接、写归档索引，并跑一次 `journal.py check`。

## 记录入口（Front-matter，固定 5 行 + 1 可选）

```markdown
# 0007 · <一句话标题>

日期：YYYY-MM-DD
变更集：N            # 无则写 -
触发：<用户请求 / 缺陷 / 计划项，一句话>
范围：<改了什么、明确不做什么>
结论：<一句话结果 + 关键数字，如「构建 0/0、测试 312 PASS」>
```

- `日期：` **必填**（校验项）。触发/范围/结论缺失只警告，但强烈建议写。
- 正文至少要有 `## 验证`；实现类记录建议含背景、方案、实施、验证、遗留五段。

## 验证段（必填）

必须能让别人复现：

```markdown
## 验证

- 命令：`<可复制执行的命令>`
- 结果：<实测输出要点 / 通过数 / 数字>
- 未覆盖：<明说没验的部分与原因；不许写"应该没问题">
```

只有"编译通过"不算验证；接口/契约类改动要给可核对的东西（样例、字节比对、负向断言）。

## 台账（`journal/README.md`）

只有一个状态区块，字段固定：

```markdown
## 当前状态（YYYY-MM-DD）

- 分支 / HEAD：
- 变更集：
- 构建：
- 测试：
- 交付物与指纹：
- 环境：
- 阻塞 / 等待：
```

规则：

1. **唯一性**：全文件只能有一个 `## 当前状态`。新增前把旧块整段剪到 `journal/archive/STATUS-HISTORY.md`。
2. **新鲜度**：日期必须 ≥ 最后一篇记录的日期；否则 `check` 警告。
3. 状态块只写**当前坐标**，不写历史；历史属于记录和 STATUS-HISTORY。
4. 待办清单只留未完成项 + 最近完成的 3–5 项（`- [x]`），旧勾选项删掉，别越堆越长。
5. 索引表每行：`| [NNNN-slug.md](NNNN-slug.md) | 一句话方面 |`；新增记录必须补一行。
6. 「同主题簇」：同一件事跨多篇时追加编号，按发生顺序排。

## 经验层（`lessons/`）

条目格式固定为一条一行（或一小段）：

```markdown
- **<症状>**：<观察到的现象>。根因：<机制>。做法：<正确做法>。（`wl/0042`）
```

规则：

1. **每条必须有来源**（`wl/NNNN` 或外部链接）；无来源的结论不许进 lessons。
2. 只写**可复用**的结论，不复制记录里的过程与数字。
3. 分册边界清晰：构建/环境、语言与 UI 生命周期、外部契约、验证与安全、事故与流程、阶段复盘。
4. 新增经验先写分册，再回填来源；来源编号必须真实存在（`check` 会校验）。
5. 阶段复盘（`99-retrospectives.md`）写阶段表、成果、可复用发现、遗留；**不要**在别处再写一份。

## 索引与链接

- 相对链接一律相对**当前文件**；跨目录用 `../`。
- 归档后旧链接要改指 `archive/<stage>/`；**git 提交信息里的旧路径不追改**（那是历史）。
- 每次收尾跑 `journal.py check`：死链、漏索引、编号断档、无来源经验都会报出来。

## 命名与语言

- 文件名：ASCII 优先；已有中文名不强制改。标题可以中文。
- 脚本类新增文件遵守仓库既有编码约定（例如本工作区要求 `.ps1` 纯 ASCII）；Python/JS 用 UTF-8。
